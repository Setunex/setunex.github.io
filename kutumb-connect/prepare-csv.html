Prepare your CSV

Three identity columns make the import behave correctly. Get these right once, and every future update just works.

The three identity columns

Column Scope Purpose
CommunityCode Whole file Which community this data belongs to. Re-importing the same code upgrades that community; a different code is added alongside it, never overwriting it.
RegionCode Whole file (optional) Sub-partition for large communities split by district/state. Leave blank if your community is imported as one file.
FamilyId One family Permanent ID for a family, stable across re-exports. Shown to family members in-app so they can quote it when requesting an update.
Never change CommunityCode once you've imported with it — the app has no other way to know two files are the same community, and a changed code is treated as a brand new one.

Option B — Prepare the CSV by hand

  1. Start from the in-app template: Import Data ▸ "Download template CSV" (works even before your first import — it uses the app's built-in sample layout).
  2. Fill one row per person. See the full field reference below for every column.
  3. Put the same value in CommunityCode (and RegionCode, if used) on every row.
  4. Give every member of one family the same FamilyId (e.g. GJ-F007) and keep it stable across future edits.

Full field reference

Column names are case-sensitive and must match exactly. Order doesn't matter — the app matches by name. Blank cells are fine for any "Optional" field.

Multiple communities in one app install

One install can hold several communities at once — each import just needs a different CommunityCode. Importing community B never touches community A's data. The first time the app sees a new CommunityCode, it asks you to name it (for confirmation dialogs only — that name is never stored in your CSV).

Large communities split across districts/states

If your community has thousands of members across regions, keep one spreadsheet per region, all sharing the same CommunityCode but each with its own RegionCode (e.g. GJ, MH). Each region's admin can update and re-import independently — re-importing one region only replaces that region, never the others.

Updating existing data

Edit your Sheet/CSV and export again with the same CommunityCode + RegionCode. The app will show a confirmation ("Replace 42 existing contacts for <Community> with 45 new ones?") before it replaces that data — it's always an explicit, reversible-by-re-import action, never silent.
